## Projects

A project is a folder on your computer. Open one with **Add project**, which has a path field, a folder browser, and a list of recent folders. You can also open a folder from your terminal with `sprocket path/to/folder`.

### Clone or create a GitHub repository

**Add project** first asks where the project comes from: **Local folder**, **Clone a repo**, or **New GitHub repo**. Local folder goes straight to the folder browser. The GitHub options ask for the repository first, then where to put it:

- **Clone a repo** takes `owner/repo` or any git URL and clones it into a new folder, named after the repository, inside the folder you pick.
- **New GitHub repo** takes a name and Private or Public. It creates the repository on your github.com account, then clones it the same way.

Both use your GitHub sign-in from Settings → Connectors. Creating a repository needs a token that can create repositories.

Sprocket identifies a project by its git `origin` remote. Every clone and worktree of the same repository shares one project and one thread list, even on different machines. A repository without an `origin` remote, or a folder outside git, is identified by its folder name, so two such folders with the same name share a project.

When you or the agent add an `origin` remote to a project that didn't have one, Sprocket moves the project's threads and artifacts to the remote's project. Threads from other folders with the same name move too, since they shared the project.

Switch projects from the project menu. **Remove** takes a project off the list without touching its files.

## Threads

A thread is one conversation with the agent. The sidebar lists a project's threads in two groups:

- **Unsettled** for threads you're still working on.
- **Settled Threads** for finished ones.

Open a thread's menu to settle or unsettle it, rename it, regenerate its title, move it to another project, copy its ID, or delete it. Deleting a thread also deletes its subagents and attachments, and you can't undo it. You can't settle, move, or delete a thread while it or its subagents are running. Sprocket names new threads for you unless you turn this off in [Settings](/reference/settings#general). It can also [settle threads when their pull requests merge](/use/github#pull-requests-in-threads).

### Search threads

Type in the search box above the thread list to show only threads whose titles match. A thread also shows when one of its subagents' titles matches. Settled matches load when you open **Settled Threads**. Press Escape to clear the search.

### Send messages

Press Enter to send and Shift+Enter for a new line. The composer accepts new messages once the current run ends. While a run is going, you can still answer the agent's questions.

Add context to a message:

| To add                | Do this                                                                                        |
| --------------------- | ---------------------------------------------------------------------------------------------- |
| Files                 | Click **Attach files**, drag them in, or paste them. Images show a preview.                    |
| A file or folder path | Type `@` and pick from the workspace.                                                          |
| A skill               | Type `$` or `/` followed by the skill name. See [Skills](/use/instructions-and-skills#skills). |

### Stop and continue

**Stop generation** ends the current run. Each running command also has its own **Stop command** button.

If a run fails or the server restarts, **Continue working** resumes the thread. Sprocket also resumes interrupted runs by itself after a restart or crash, unless you turn this off in [Settings](/reference/settings#general).

### Read the agent's work

Work blocks summarize what the agent did, such as "Ran 3 commands", and show whether the work is still running. Running work opens by default. Open a block to see its tools and reasoning. A long block shows its newest 200 items first. Click **Show earlier** to load older ones. Reasoning starts closed, even while the agent is thinking. Click a reasoning row to read it. An open row updates as the agent reasons.

Tool rows show a one-line summary. Click a command, question, subagent, or patch row to read the full text, with commands syntax highlighted. Click a parsed file row to open the file in the file viewer. Hover any other row to see a summary that doesn't fit. Checkout results keep their **Save card** action after a reload.

### Subagents

The agent can start subagents to work on parts of a task in parallel. Each subagent is its own thread and appears under its parent in the sidebar. See [Subagents](/use/agent-tools#subagents).

## Workspace tabs and panels

The main workspace has tabs and panels. Each thread, and the new-thread screen, starts with a **Thread** tab that holds the conversation and message composer. You can switch away from it, but you can't close it. Tabs you open on the new-thread screen stay with the thread it creates.

Use **New tab** to open a view, or **Split right** and **Split down** to add panels. Drag a divider to resize panels. Each thread keeps its own tabs and panel sizes until you reload the app.

New tabs offer three views:

- **Artifacts** shows files the agent linked to the project, rendered. See [Artifacts](#artifacts).
- **Files** is a file tree where you can search, create, rename, delete, and edit files. The editor asks before it discards unsaved changes.
- **Browser** shows the browser the agent controls.

### Artifacts

An artifact is a project file the agent bound for you to view. Edits to the file show up in the artifact. Sprocket renders each artifact based on its file name:

| File name ends with | Renders as                                                               |
| ------------------- | ------------------------------------------------------------------------ |
| `.html` or `.htm`   | A web page                                                               |
| `.jsx`              | A React component                                                        |
| `.render.json`      | A [json-render](https://json-render.dev) spec using the app's components |
| `.wiring.json`      | A [wiring diagram](/use/hardware#wiring-diagrams)                        |
| Anything else       | Markdown                                                                 |

### Rich replies

Agent replies render GitHub-flavored Markdown plus:

- Inline HTML and React visuals.
- Mermaid diagrams.
- Math with KaTeX.
- KiCad project cards with schematic, PCB, and 3D views. See [Hardware](/use/hardware#view-designs).
- Artifact cards.
- Code blocks with syntax highlighting and a copy button.

### Usage per thread

The **AI usage** button in a thread shows what the thread and its subagents cost at direct API prices.
